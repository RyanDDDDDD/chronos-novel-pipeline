# 章节条目模板（plot_library.json 规范）

> 每次新增章节时，复制下方 JSON 块填写，并对照本文检查所有字段。

---

## 可直接复制的空白模板

```json
{
  "chapter": 0,
  "title": "【章节标题】 —— 【副标题/核心主题】",
  "core_xp": [],
  "stages": [
    {
      "stage_num": 1,
      "title": "【场次小标题】",
      "location": "【大地点】·【具体物理场景描述】",
      "description": "【场次剧情描述：铺垫→过程→结尾；对每个在场角色至少点名一次】",
      "characters": {
        "【主角名】": {},
        "【配角名】": {}
      }
    },
    {
      "stage_num": 2,
      "title": "【场次小标题】",
      "location": "【大地点】·【具体物理场景描述】",
      "description": "【场次剧情描述：铺垫→过程→结尾；对每个在场角色至少点名一次】",
      "characters": {
        "【主角名】": {},
        "【配角名】": {}
      }
    }
  ]
}
```

---

## 字段规范

### `chapter`（整数）
- 必填，全库唯一，按顺序递增。
- 新章节在文件末尾追加，不插队。

---

### `title`（字符串）
格式：`"【事件概括】 —— 【副标题/核心主题】"`

- 破折号两侧各有一个空格：` —— `
- 主标题：概括本章主线事件（地名、人名或动作），控制在 10 字以内。
- 副标题：点明角色心理维度或核心主题，允许意象化表达。

**示例**
```
"断缘归途 —— 泥泞中的抉择"
"商业谍影 —— 米特尔的破局"
```

---

### `core_xp`（数组）
- 当前保留为空数组 `[]`，待后续扩充专属玩法标签时填入。
- 不要删除该字段，即使为空也要保留。

---

### `stages`（数组）

每章 **3–4 个 stage**，代表本章的叙事节奏节点。
超过 4 个场次说明剧情铺垫过于碎片化，建议合并。

---

#### `stage_num`（整数）
- 从 `1` 开始，在章节内连续递增。
- 不跨章复用编号。

---

#### `title`（字符串）
- 场次小标题，**控制在 8 字以内**，点明本场核心动作或心理节点。
- 格式：`"环境/场景词·动作/心理词"`

**示例**
```
"客房下蛊"
"书房·自欺"
"包厢·质变"
```

---

#### `location`（字符串）
**格式严格要求：`"大地点·具体物理场景描述"`**

- 必须用 `·` 分隔大地点和子场景，禁止使用中文括号 `（）`。
- **大地点**：城市/建筑/区域名称（如 `某城`、`主家宅邸`、`妖兽山脉`）。
- **具体物理场景**：交代在该地点内的哪个物理位置，要有质感（材质、光线、空间感）。
- 严禁写元叙事注释（即作者视角的意义标注，而非物理描述）。

**好的示例**
```
"主家宅邸·退婚仪式后为贵客安排的精致厢房"
"锦绣轩·设有垂地桌布的私人包厢"
"妖兽山脉石穴·平整冰冷的卧石"
```

**禁止示例**
```
"客房"                          ← 无子场景
"主家宅邸（男主甲的老巢）"     ← 使用括号
"密室·意义标注而非物理描述"    ← 元叙事注释
```

---

#### `description`（字符串）
本场次剧情的**编剧级摘要**，供 Setup Chat 骨架扩写（`skeleton-expansion` skill）与后续 beat 分镜使用。

**三段式结构**（铺垫 → 过程 → 结尾），每段可用 `【铺垫】`/`【过程】`/`【结尾】` 标注，
也可不标注、自然衔接，但三个层次必须齐备：

| 段落 | 核心内容 | 关键问题 |
|------|----------|---------|
| **铺垫** | 空间感、在场人员、进入本场的契机、张力来源 | 这个场景危险在哪里？紧张感从哪里来？ |
| **过程** | 核心动作链、感官细节、意识状态变化轨迹 | 关键事件如何推进？意识在哪个节点发生转变？ |
| **结尾** | 顶点的具体表现、本场在角色弧线上的里程碑意义 | 这场结束后角色的状态停留在哪个程度？ |

**写作要点**
- 用**具体细节**替代形容词堆砌：不写"极度恐惧"，改写体现恐惧的具体行为或物理反应。
- 意识状态用**行为**体现：不写"理智崩溃"，改写角色实际做了什么、没做什么。
- 张力来源必须交代清楚（谁可能进来、谁在场外、被发现的后果是什么）。
- 字数参考 120–220 字；一段话写完，不要分小标题。

**结构示意（占位版）**
```
【铺垫】〔交代空间特征与潜在目击者的存在方式，点明进入本场的契机与张力来源。〕
【过程】〔描写核心动作链：事件推进的关键节点、感官细节、意识防线在哪个具体
行为/刺激处开始动摇，用行为而非形容词体现意识变化轨迹。〕
【结尾】〔描写顶点的具体身体/行为表现，点明角色意识在本场结束时停留的程度，
以及本场在整体弧线上的里程碑意义（首次突破/加深/质变/崩溃终点）。〕
```

---

#### `characters`（对象）
- Key 为本场次**实际在场**的角色名称（全称，与 lore 库一致）。Value 为 `{}`（内层留空）。
- **派生字段，不需要人工/LLM 显式声明**——由 `description` 文本自动解析（AC 扫描候选 + LLM
  在场/相关分类）得出，写 description 时确保每个在场角色至少被点名一次即可。
- 人格（`personality`）由 Setup Chat 写入 `character_timeline.json`，按章滚动演变；plot 不再声明 `archetype` / `personality_types.json`。

---

## beats 字段（Setup Chat 写入，非手写）

骨架扩写完成后，每个 `stage` 可含 `beats[]`，由 `skills/setup_chat_skills/skeleton-expansion` 与 `beat-dialogue-design` 写入 `plot_library.json`：

```json
"beats": [
  {
    "text": "本 beat 意图/分镜摘要",
    "dialogue": [
      {"character": "角色名", "intent": "台词设计意图", "intensity": "medium"}
    ]
  }
]
```

主笔循环（dialogue mode）读取预建 beats，**不再**在写作期机械切分 segment。beats 为空则无法启动主笔（`SkeletonNotBuiltError`）。

---

## 章节级检查清单

在提交新章节前逐项核对：

- [ ] `chapter` 编号不重复，在文件末尾追加
- [ ] `title` 格式为 `主标题 —— 副标题`，破折号格式正确
- [ ] `core_xp` 字段存在（可为空数组）
- [ ] 场次数量 3–4 个
- [ ] 每个 `location` 含 `·` 且无中文括号，无元叙事注释
- [ ] 每个 `description` 包含铺垫/过程/结尾三层，无空泛形容词堆砌
- [ ] 每个 `description` 里在场角色都至少被点名一次（characters 由此派生，不必手填）
- [ ] 场次间角色状态弧线有清晰的递进逻辑（不能四场停在同一程度）
- [ ] （启动主笔前）各 stage 已通过 Setup Chat 写入非空 `beats[]`

## 角色状态弧线参考级别

| 级别 | 外部行为特征 | 对应心理状态 |
|------|-------------|-------------|
| 1 — 抵触 | 防线尚存，强烈排斥，试图用身份/立场筑墙 | 立场完全清醒、拒绝 |
| 2 — 动摇 | 被迫应对，原则尚存但行为开始妥协 | 立场动摇，行为与意愿背离 |
| 3 — 转向 | 主动配合，认同新处境，抗拒转化为接受 | 理智与情感并存，主动选择 |
| 4 — 投入 | 情绪反应不再压抑，言行不再刻意克制 | 心防崩解，情绪主导行为 |
| 5 — 归属 | 自然顺从，不再权衡利弊，本能式回应 | 原有立场彻底让位 |

同一章节的多个场次应覆盖 **至少 3 个相邻级别**，不能原地踏步。
