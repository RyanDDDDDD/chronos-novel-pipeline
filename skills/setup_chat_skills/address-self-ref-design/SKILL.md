你在为角色推演 timeline delta。**称呼（address_ref，你怎么称呼别人）和自称（self_ref，你怎么称呼自己）是同一件事的两面**——都是角色关系与心理状态在语言上的投影。实测发现 agent 系统性只顾 address_ref、几乎从不更新 self_ref：如果本 stage 触发了"滑块门控字段"的更新条件（档位真的变了），**两者都要认真过一遍，不能只想 address_ref**。

## 为什么 self_ref 更容易被漏掉，以及为什么不该漏

称呼对方是"演给对方看"的，容易观察也容易联想（关系近了自然会换个更亲昵的叫法）；自称是"她怎么看自己"，往往更沉默、更容易被忽略——但恰恰因为如此，**自称的变化常常比称呼更能暴露真实的心理转变**：一个人还愿不愿意用"我"称呼自己、还记不记得自己的名字、会不会开始用关系身份定义自己，这些比"嘴上叫对方什么"更接近角色内心真实的靠近程度。别让自称沦为称呼的附庸，该给信号时自称要主动给。

## 自称演变方向（题材中性，只是"何为一次真实的演变"的示范，不是词表）

- **正式自称 → 爱称/小名**：从完整称谓收窄成对方给的昵称，暗示关系拉近或人格边界软化。
- **独立自称 → 关系身份自称**：比如从"我"变成用对方赋予的身份/称号指称自己（慎用——必须真的贴合当下心理转变，不能为了"有变化"而套用，亲密度没到那一步就别用）。
- **对不同对象分化**：对最亲近的对象自称更软、更依赖或更亲昵；对其他人保持原样——同一角色在不同关系里可以有不同自称，池子里按对象分开给即可（`self_ref` 本就支持 per-target 覆写）。

## 一个完整示例（占位角色，脱敏）

角色 A 与角色 B 的关系持续加深，某章第 2 拍 sliders「亲密度」从 level 1 升到 level 2：

```json
{
  "sliders": {"亲密度": {"level": 2, "text": "……"}},
  "address_ref": {"B": ["小名"]},
  "self_ref": {"_default": ["我"], "B": ["人家"]}
}
```

不要只给 `address_ref`（称呼从"你"变成"小名"）却漏了 `self_ref`——亲密度真的推进到"愿意用更亲昵的方式指称自己"这一步时，`self_ref` 对 B 的覆写条目（"人家"）就是这次转变最直接的语言信号，比称呼变化更有说服力。

## 门控规则不变

仍然遵守 timeline-derivation 的滑块门控规则——**不是要求每次都变**，档位没推进就两个字段都别写。这条技能只是提醒：档位真的推进了的时候，**别让 self_ref 被 address_ref 抢走全部注意力**。

脱敏：你自己举例/打比方用通用占位词；用户写同人时设定内容照用原作专名，不在此列。
