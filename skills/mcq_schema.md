# 出题输出契约（引擎统一注入·最高优先级）

> 本契约由引擎在「出题轮」自动注入到出题 System 末端，是**所有出题 agent 唯一的结构规范**。
> agent 的领域 prompt 只描述「出什么题、几个选项、label 写什么」，**不再自述 JSON 结构**——结构以本契约为准。

## 输出格式（机器契约，严格遵守）

**只输出纯 JSON，不加任何 Markdown 代码块（``` ）、不加解释文字。** 顶层结构：

```
{"sections": [
  {"title": "...", "status": "ok", "assessment": "...",
   "options": [{"id": "a", "label": "..."}, {"id": "b", "label": "..."}]}
]}
```

> 混用轮（同一轮内不同题控件类型不一致）时，才在 section 上逐题写 `"type": "radio"` 或 `"checkbox"`。

## 字段规则

- **`sections`**：题目数组。**每段一题时，section 数必须等于段数、顺序与段一致**（第 1 个 section = 第 1 段）。
- **`title`**：题面（口语化，引用本段场景）。
- **`type`**：**由引擎按轮声明（`## ROUND <qtype> <radio|checkbox>`）统一设定，agent 默认不要写**；仅当一轮内不同题控件类型不一致时，才逐题写 `type`。
- **`status`**：固定 `"ok"`（异常兜底题可用 `"warn"`）。
- **`assessment`**：一句话说明本题在选什么（可空字符串 `""`）。
- **`options`**：选项数组，规则见下。

## 选项铁律（最易错，务必遵守）

1. **每个 option 必须是独立对象** `{"id": "x", "label": "..."}`，以逗号分隔。**严禁把选项写成裸字符串**（`["甲","乙"]` ✗）。
2. **`id`** 用小写字母 `a`、`b`、`c`…依次编号；特殊项用语义 id（如 `keep`/`skip`）。
3. **`label`** 是选项正文（一句话说清这个选项是什么）。
4. **严禁把多个 option 塞进同一个 `{}`**——一个 `{}` 只能有一个 `id`。多选项 = 多个 `{}`。
5. option **可带额外字段**（如 `"actions"`、`"chain"`），引擎透传不干预；但 `id`+`label` 必填。
6. **严禁在 label 或任何字符串值后多写 `]`**（会让 options 数组提前关闭、丢选项）。

## 自检（输出前过一遍）

- [ ] 是纯 JSON、无代码块、无前后解释？
- [ ] 每个 option 都是独立 `{id,label}` 对象、不是裸字符串？
- [ ] 没有把多个 id 塞进一个 `{}`？
- [ ] 每段一题时 section 数 = 段数、按序排列？
- [ ] （混用轮才）逐题写了 type 吗？
